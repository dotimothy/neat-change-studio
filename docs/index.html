See What Changed

Powered by Neat · Modalix MLA

Give it a before photo and an after photo of the same scene. It draws boxes around what appeared, disappeared or changed, on the SiMa.ai Modalix MLA. The model is CYWS (The Change You Want to See, WACV 2023), DINOv2 used zero-shot, or C-3PO change segmentation, each compiled to one MLA ELF and run through NEAT.

Install

Three Commands on the Board

Run these on a Modalix DevKit with the Neat SDK and its pyneat environment. The first install needs internet access.

01

Install

Fetches the Studio into ./neat-change-studio: about 4 MB, with no models. You download a model in step 02 or later from the web demo. Run it in /media/nvme, which has room for the models.

Board
$ cd /media/nvme && curl -fsSL https://raw.githubusercontent.com/dotimothy/neat-change-studio/main/install.sh | bash
02

Set Up

Installs any missing Python packages into the pyneat environment, downloads a model from Hugging Face (bf16 unless you pick another) into the shared models directory, /media/nvme/models/cyws, makes the HTTPS certificate, and offers to add the neat-change command and, on a board with a desktop, a desktop icon. CYWS_MODELS=all fetches bf16, w8a16 and dinov2-448 without asking.

Board
$ cd neat-change-studio && ./setup.sh
03

Run

Starts the web demo and prints the address to open. Open a new shell first (or run source ~/.bashrc): the alias is not yet defined in the shell that ran setup. Without the neat-change alias, run webapp/run.sh instead.

Board
$ neat-change                # web demo on https://<board-ip>:8098 (and http://)
$ neat-change --daemon       # or in the background; --stop stops it
$ ./run.sh --mode static --before b.jpg --after a.jpg   # or the CLI on one pair

What You Need

To Run It

  • A Modalix DevKit with the Neat SDK 0.5.0 (platform 2.1.3) and its pyneat venv, in ~/pyneat or set by PYNEAT_VENV.
  • Internet access on the board for the first install and the model download.
  • numpy, OpenCV 4.4 or later (for SIFT), Pillow and Flask. ./setup.sh installs what is missing; ./setup.sh --check-only only checks.

To Build the Model (Optional)

  • uv, Python 3 and PyTorch on the host.
  • The SiMa Neat SDK container with the Model Compiler.

The bf16 model needs no calibration photos. From the repo, on an x86 host (about 10 minutes):

Host
$ STEPS=setup ./run_all.sh
$ model/fetch_upstream.sh
$ .venv/bin/python model/export_onnx.py
$ compile/compile.sh --precision bf16 --out build/bf16

This writes build/bf16/cyws_bf16_mpk.tar.gz (one MLA ELF, no A65 stage). ./run_all.sh reproduces everything, including w8a16 (which needs your own before/after photos for calibration) and the board evaluation. Step-by-step guide.

Update

Fetches the latest source over the install, keeps your models, data, outputs and certificate, then runs ./setup.sh again.

Board
$ neat-change update

From a Host Instead

From a clone of the repository, deploy.sh copies the app to the board over ssh and rsync and runs setup.sh there.

Host
$ BOARD=sima@<devkit-ip> ./deploy.sh
$ BOARD=sima@<devkit-ip> ./deploy.sh --with-data   # also copy data/testCYWS

testCYWS is the author's private set and is not published, so bring your own pairs in this layout: images/<id>_ref.jpg (before), images/<id>_cap.jpg (after) and, for metrics, masks/<id>.jpg. The default folder is data/testCYWS; set CYWS_DATA to use another one, and run the whole set with ./run.sh --mode dataset.

Only one app may use the MLA at a time, so stop other demos first. The web demo can also load, unload, download, verify, re-download and delete models itself, in its Models window. Every download is checked against its SHA-256.

How It Works

One Network, Two Photos, One MLA ELF

CYWS is a Siamese ResNet-50 U-Net with co-attention and a CenterNet head. It looks at both photos at once and predicts objects on each side. The whole network runs as a single MLA ELF, with no stage on the A65 CPU; the CPU only decodes the photos and crops the windows.

The Model

Beforein0_before256×256 RGB
Afterin1_after256×256 RGB
One MLA ELF
ResNet-50 EncoderShared weights, one pass per photo
Co-AttentionEach photo's features attend to the other's, so what is missing or new stands out
U-Net Decoders + CenterNet HeadPer side: heat map, box size and offset at 256×256
One Fused Output(10, 256, 256)heat, size, offset for before and after
On Both Sides: Changed Only in After: Appeared Only in Before: Disappeared

The ONNX graph has 49.47M parameters and about 75 GMAC per pair. Peaks in each side's heat map become boxes; a before box and an after box that overlap are merged into one changed box.

Tiling for 12 MP Photos

The model was trained on 256×256 inputs, and a phone photo is 12 MP. Small objects vanish when the whole photo is shrunk to 256, so the app tiles it.

  • Global window first. The whole photo runs once.
  • Gated tiles next. Tiles of 0.45 × the short side run only where the global heat is at least 0.25.
  • Merge. Boxes from all windows are mapped back to the photo and merged.

On the test set the balanced preset runs 3.4 windows per pair on average.

Compiling to One ELF

A self-contained rewrite (model/cyws_mla.py) loads the upstream checkpoint with 0 missing and 0 unexpected keys and changes only how the math is written. Each change came from a probe compile that failed:

  • BatchNorm folded; co-attention written as Split/Concat, Einsum and Softmax.
  • scSE gate: the 1-channel spatial gate is expanded with a fixed 1→C conv of ones, because two broadcast multiplies failed to compile.
  • The 6144→256 3×3 decoder conv is split into 3 input-channel chunks, because the single conv failed after "large tensor support".
  • The CenterNet head is fused, and all outputs go into one tensor so they cannot be swapped.

Result in bf16: one MLA ELF plus 7 EV74 plugins, no A65 stage. Against upstream in float64 the rewrite differs by at most 1.2e-12.

A Second Model: DINOv2, Zero-Shot

DINOv2 ViT-S/14 with 4 registers is a general image feature extractor, compiled to one MLA ELF with no A65 stage (4 EV74 plugins): one 448×448 image in, a feature for each of its 32×32 patches out, in 24.5 ms (50 images/s, 14.0 W). Both photos go through it, and so do overlapping tiles. A patch of the after photo with no similar patch nearby in the before photo is new; one of the before photo with no match in the after photo is gone. Nothing is trained for change detection.

A Third Model: C-3PO, Change Segmentation

C-3PO (Wang et al., Pattern Recognition 2023; MIT) segments what changed between a before and an after image, 256×256 each: a ResNet-18 shared by both photos, an MTF module that merges them as appeared, disappeared and exchanged, MSF over four scales and a DeepLabV3 head. It compiles to one MLA ELF with no A65 stage and runs in 46.7 ms per pair (24.5 pairs/s, 12.8 W). Two released checkpoints are compiled: PCD (street panoramas) and ChangeSim binary (a simulated indoor factory). They are binary, so every box is labelled changed.

Neither checkpoint was trained on photos like these, and C-3PO is behind CYWS and DINOv2 here. The threshold was tuned on these same pairs with ONNX Runtime FP32 on a PC (bf16 agrees with FP32 on 99.98% of mask pixels); the 46.7 ms is Model.benchmark's, while a plain pyneat push → pull loop on the board took about 447 ms per pair, and the studio's own time on the board is still to be measured.

Presets, Windows and Threshold

Fast runs the global window only, Balanced adds tiles where the global heat map saw a change, and Accurate runs every tile. The threshold, the windows and photo alignment can be set by hand.

Each change re-runs straight away. The decoded photos are cached, so a re-run takes about half a second on the board.

Webcam

Capture, Change, Capture

Capture Before, change something, then capture After. A self-timer (3, 5 or 10 s) counts down before each shot, and a faint ghost of Before helps line up After.

While you line up After, an alignment check compares the camera with Before in the browser, with OpenCV.js in a Web Worker. It scores the match, draws the Before frame's outline on the live view and an arrow to move the camera by, and can be turned off with the Align button.

Watch Live then compares every new frame with Before and keeps the result up to date, at about 2 frames/s on the board with a 1080p webcam, most of it capture and upload. Browsers allow the camera only on HTTPS, so port 8098 speaks both HTTP and HTTPS.

Models

A Model Manager in Its Own Window

The Models window, opened from the header, has a card for each model on the board, and under Add Model the compiled models on dotimothy/sima-cyws and dotimothy/sima-dinov2. Load switches the MLA over and Unload frees it for other apps. A model that is not on the board downloads with progress, cancel and resume, and its SHA-256 is checked before it can be loaded. Models on the board can be verified, re-downloaded or deleted, a storage bar shows the space they use, and each card opens a Model Card with the model's facts.

On a fresh board, the first model downloaded loads by itself.

Enlarge: Phone

Phone

The Same Page, With a Tab Bar

On a phone the page switches to a tab bar for Detect, Test Set, Results and Settings. Photos can be taken with the phone's camera and are shrunk to a 2048 px long side in the browser before upload, which makes the upload and the board's decode several times faster.

Where It Fails

  • Objects of about 60 px in a 12 MP photo are missed. Native resolution with three tiling levels at thr 0.2 finds 4 of 7, at the cost of 12 false-alarm pairs and 178 windows per pair.
  • Camera parallax can cause a false alarm. --register (SIFT + MAGSAC, then a ZNCC check) removes one such case, at about 0.6–0.85 s of A65 time per pair.
  • One no-change pair may have a GT mask that is too faint rather than an unchanged scene.

The board stays within 0.01 F1 and one component of FP32 on the host (34/47, F1 0.594).

Models

Compiled Models

Every model is a single-ELF MPK for the Modalix MLA: the two CYWS builds in dotimothy/sima-cyws and DINOv2 in dotimothy/sima-dinov2, both in the collection SiMa.ai Change Detection Models. Download them from the web demo's Models window, with ./setup.sh, or with neat-change --fetch bf16 (or w8a16, dinov2-448). They go to one models directory, /media/nvme/models/cyws, shared by every install and kept across updates; ./setup.sh --models-dir DIR moves it. The two C-3PO models are not on Hugging Face: copy their MPKs into that directory, or compile them with the C-3PO port.

Upstream C-3PO

Latency is Model.benchmark. testCYWS numbers use the balanced preset, and the settings of every family were tuned on those same pairs, so they are optimistic for new scenes. The CYWS models take in0_before and in1_after (float32 256×256×3 HWC, RGB, pixel / 255) and return one fused (10, 256, 256) output. DINOv2 takes one float32 448×448×3 image (RGB / 255) and returns (1, 384, 1, 1029): a class token, 4 registers and 32×32 patch features; a pair is two images per window. C-3PO takes in0_before and in1_after (float32 256×256×3 HWC, RGB / 255) and returns logits (1, 2, 64, 64); its testCYWS numbers are FP32. A plain pyneat push → pull loop on the board took about 447 ms per C-3PO pair, against 46.7 ms from Model.benchmark.
